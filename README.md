# FRIENDS HOLD'EM — 멀티플레이 텍사스 홀덤

서로 다른 장소의 **2~4명이 각자 자신의 브라우저**로 같은 서버에 접속해 플레이할 수 있는 멀티플레이 텍사스 홀덤입니다.

방 생성 및 참가, 대기실, 개인별 홀 카드, 공통 게임 상태 동기화, 재접속, 턴 제한, Side Pot 등 실제 홀덤 진행에 필요한 주요 기능을 구현했습니다.

## 🎮 바로 플레이

별도의 설치 없이 아래 주소에 접속하면 바로 플레이할 수 있습니다.

**게임 접속 주소**

https://holdem-dhxf.onrender.com

1. 한 명이 사이트에 접속해 방을 생성합니다.
2. 생성된 **8자리 방 코드**를 친구들에게 전달합니다.
3. 친구들이 같은 사이트에 접속해 방 코드를 입력합니다.
4. 정해진 인원이 모두 입장하면 방장이 게임을 시작합니다.

> Render 무료 서버의 경우 일정 시간 사용하지 않으면 서버가 절전 상태가 될 수 있어, 첫 접속 시 서버가 시작되는 데 시간이 조금 걸릴 수 있습니다.

- 2~4인 온라인 멀티플레이

- 각 플레이어의 개인 홀 카드 보호

## 플레이 순서

1. 게임 주소에 접속합니다.

   https://holdem-dhxf.onrender.com

2. 닉네임을 입력하고 **2 / 3 / 4명** 중 플레이 인원을 선택한 뒤 **방 만들기**를 누릅니다.

3. 친구에게 게임 주소와 화면에 표시된 **8자리 방 코드**를 전달합니다.

4. 친구들은 각자의 브라우저에서 같은 주소에 접속한 뒤 방 코드를 입력해 **참가**합니다.

5. 정해진 인원이 모두 모이면 방장이 **게임 시작**을 누릅니다.

6. 각 플레이어는 자신의 패만 확인할 수 있으며 자신의 턴에만 행동 버튼이 활성화됩니다.

7. 핸드가 종료된 뒤 방장은 **Next Hand** 또는 **New Game**을 선택할 수 있습니다.

   - **Next Hand**: 현재 칩 상태를 유지하고 다음 핸드를 시작합니다.
   - **New Game**: 현재 인원과 좌석을 유지하면서 칩을 초기화합니다.

한 PC에서 여러 명을 테스트하려면 주소를 새 탭에 직접 입력하거나 서로 다른 브라우저를 사용하는 것을 권장합니다.

브라우저의 **탭 복제** 기능은 `sessionStorage`까지 복사할 수 있기 때문에 같은 플레이어의 좌석으로 접속될 수 있습니다.

## 로컬 실행

직접 서버를 실행하거나 개발 환경에서 테스트하려면 **Node.js 22 이상**이 필요합니다.

참가자는 브라우저만 있으면 됩니다.

외부 npm 패키지를 사용하지 않기 때문에 별도의 `npm install` 과정은 필요하지 않습니다.

프로젝트의 `holdem` 폴더에서:

```sh
node server.js
```

또는:

```sh
npm start
```

실행 후 브라우저에서 다음 주소로 접속합니다.

```text
http://localhost:3000
```

**`index.html`을 직접 더블클릭하거나 정적 파일 서버만 실행해서는 멀티플레이가 동작하지 않습니다.**

Windows에서는 터미널 명령 대신 `start-server.cmd`를 더블클릭해 서버를 실행할 수도 있습니다.

서버 창을 닫으면 게임 서버도 종료됩니다.

## 배포

현재 게임은 **Render**에 배포되어 있으며 아래 주소에서 실행할 수 있습니다.

https://holdem-dhxf.onrender.com

멀티플레이 게임 특성상 단순 정적 HTML 호스팅이 아닌 **지속적으로 Node.js 서버를 실행할 수 있는 환경**이 필요합니다.

### 서버 설정

- 실행 명령: `node server.js`
- 기본 포트: `3000`
- 호스팅 환경에서 `PORT` 환경 변수가 제공되면 해당 포트를 자동으로 사용합니다.
- 기본 바인딩 주소: `0.0.0.0`
- 필요 시 `HOST` 환경 변수로 변경할 수 있습니다.
- HTTPS는 호스팅 플랫폼 또는 리버스 프록시에서 처리합니다.
- API와 웹 화면은 같은 Origin에서 제공됩니다.
- 프록시는 원래 Host 헤더를 보존해야 합니다.

게임 진행 상태가 서버 메모리에 저장되기 때문에 기본적으로 **Node 프로세스 / 인스턴스 1개**를 기준으로 동작합니다.

여러 서버 인스턴스로 자동 분산하려면 별도의 공유 세션 / 게임 상태 저장소가 필요합니다.

## 네트워크와 재접속

- 클라이언트는 약 **0.8초 간격**으로 개인화된 최신 게임 상태를 조회합니다.
- 플레이어의 행동은 즉시 서버에 POST 요청으로 전송됩니다.
- WebSocket이 아닌 **HTTP Polling 방식**을 사용합니다.
- 각 좌석은 무작위 **256비트 참가 토큰**으로 인증합니다.
- 참가 토큰은 URL이나 쿠키가 아닌 `Authorization` 헤더로 전달됩니다.
- 참가 토큰은 브라우저 탭의 `sessionStorage`에 저장됩니다.
- 같은 탭에서 새로고침하거나 일정 시간 안에 연결이 복구되면 기존 좌석을 유지합니다.
- 게임 진행 중 **20초 이상 요청이 끊기면 해당 플레이어는 리타이어 처리**됩니다.
- 리타이어된 플레이어는 같은 방에 다시 접속하더라도 기존 게임으로 복귀할 수 없습니다.
- 진행 상태는 서버에 저장되므로 참가자의 새로고침으로 게임이 초기화되지 않습니다.
- 자신의 턴이 아니거나 오래된 상태를 기준으로 요청하거나 요청을 중복 전송하면 서버에서 거부합니다.
- 칩, 카드, 승자 판정 등 중요한 게임 상태는 클라이언트를 신뢰하지 않고 서버에서 처리합니다.

### 턴 제한

각 플레이어의 턴 제한 시간은 **60초**입니다.

시간이 초과되면:

- Check가 가능하면 → **Check**
- Check가 불가능하면 → **Fold**

로 자동 처리됩니다.

연결이 끊긴 플레이어 때문에 현재 핸드가 무기한 멈추는 것을 방지합니다.

### 접속 상태

마지막 요청 시간을 기준으로 플레이어의 연결 상태를 판단합니다.

**10초 이상 요청이 없으면 연결 끊김 상태로 표시**합니다.

## 포커 규칙

- 시작 칩: **10,000 Chip**
- Small Blind: **100**
- Big Blind: **200**
- 첫 Dealer는 Player 1입니다.
- 이후 Dealer는 생존 플레이어 좌석을 기준으로 이동합니다.

### Heads-Up

2명이 플레이하는 Heads-Up에서는:

- Dealer가 Small Blind
- Dealer가 Pre-Flop 첫 행동
- Big Blind가 Flop 이후 첫 행동

을 수행합니다.

### 행동

다음 행동을 지원합니다.

- Fold
- Check
- Call
- Raise
- All-In
- 자동 Call All-In

Raise 입력값은 현재 스트리트의 **누적 베팅 총액**입니다.

직전 정상 Raise의 증가폭 이상으로 Raise해야 하며, 스택이 부족한 경우 All-In으로만 짧게 인상할 수 있습니다.

짧은 All-In에 대한 **콜 기회와 재레이즈 권한을 별도로 처리**합니다.

누적 인상 금액이 정상 Raise 폭에 도달하면 다시 Raise할 수 있습니다.

모든 활성 플레이어의 베팅 금액과 행동 완료 여부를 확인한 뒤 다음 스트리트로 진행합니다.

Pre-Flop에서는 Big Blind의 행동 기회를 유지합니다.

## 카드와 승자 판정

- 52장 카드 덱을 사용합니다.
- 스트리트마다 Burn Card를 처리합니다.
- 서버의 카드 셔플에는 Node.js `crypto` 기반 난수를 사용합니다.
- 7장의 카드 중 가장 강한 5장을 완전 탐색하여 족보를 판정합니다.

다음 포커 족보를 모두 처리합니다.

1. High Card
2. One Pair
3. Two Pair
4. Three of a Kind
5. Straight
6. Flush
7. Full House
8. Four of a Kind
9. Straight Flush
10. Royal Flush에 해당하는 Ace-high Straight Flush

추가로:

- Kickers
- A2345 Wheel Straight
- 동일 족보 비교
- 완전 동점
- Pot 분할

을 처리합니다.

## Main Pot / Side Pot

각 플레이어의 실제 기여 금액을 기준으로:

- Main Pot
- Side Pot

을 자동 계산합니다.

Fold한 플레이어가 이미 베팅한 금액도 Pot에는 포함되지만 승리 자격에서는 제외됩니다.

상대가 Call하지 못한 금액은 반환됩니다.

Pot을 나눌 때 발생하는 홀수 칩은 **Dealer 왼쪽 플레이어부터** 지급합니다.

---

## Showdown

Showdown에서는 Fold하지 않은 플레이어의:

- Hole Cards
- 최종 족보
- Best 5 Cards

를 공개합니다.

상대 플레이어가 모두 Fold하여 승리한 경우에는 상대방의 카드를 공개하지 않습니다.

칩이 `0`이 된 플레이어는 다음 핸드부터 제외됩니다.

마지막으로 남은 플레이어를 최종 우승자로 표시합니다.

---

## 닉네임

방 생성 또는 참가 전에 닉네임을 **최대 20자**까지 입력할 수 있습니다.

닉네임을 입력하지 않거나 공백만 입력하면 좌석에 따라:

```text
Player 1
Player 2
Player 3
Player 4
```

형태로 표시됩니다.

닉네임은 다음 UI에 반영됩니다.

- 대기실
- 플레이어 프로필
- 현재 턴
- 게임 로그
- 행동 알림
- 승리 알림

동일 세션의 재접속과 New Game에서도 닉네임을 유지합니다.

## 진행 중 퇴장과 리타이어

서버가 플레이어로부터 **20초 동안 요청을 받지 못하면 퇴장으로 판단**합니다.

다음 상황도 동일하게 처리될 수 있습니다.

- 브라우저 창 종료
- 장시간 네트워크 단절
- 기기 절전
- 브라우저의 장시간 백그라운드 정지

퇴장 플레이어는 현재 핸드에서 다음 자기 행동 차례에 자동으로 Fold됩니다.

이미 Fold한 경우 추가 행동은 발생하지 않습니다.

이미 All-In하여 행동이 끝난 플레이어는 현재 Pot의 승리 자격을 유지하고 해당 핸드 정산이 끝난 뒤 제외됩니다.

다음 핸드부터는:

- 카드 배분
- Dealer
- Blind
- 행동 순서

에서 제외됩니다.

New Game을 실행해도 퇴장한 플레이어는 복귀하지 않습니다.

이미 Pot에 들어간 베팅 금액은 그대로 유지됩니다.

기권 플레이어의 남은 칩은 `0`으로 처리되며 다른 플레이어에게 직접 지급되지 않습니다.

남은 참가자가 한 명이면 현재 핸드 정산 후 최종 우승자로 결정됩니다.

모든 플레이어가 퇴장하면 우승자 없이 게임이 종료됩니다.

방장이 퇴장하면 남아 있는 플레이어에게 방장 권한을 자동으로 넘깁니다.

## 기권 버튼

게임 화면 오른쪽 아래에 **게임 기권 버튼**이 있습니다.

버튼을 누르면 확인창이 표시되며 실제 기권을 확정해야 적용됩니다.

기본 포커스는 **계속 플레이**입니다.

직접 기권과 20초 이상 연결 종료는 동일한 기권 상태로 처리합니다.

기권 시:

- 현재 핸드의 다음 자기 차례에 Fold
- 다음 핸드부터 게임 제외
- 동일 방 복귀 불가
- 이미 All-In한 경우 현재 핸드 정산 자격 유지

가 적용됩니다.

기권한 플레이어는 화면에서 **기권 · 패배** 상태로 표시됩니다.

핸드가 이미 끝난 뒤 상대방의 기권으로 최종 우승자가 결정되는 경우에도 최종 우승 안내가 표시됩니다.

```text
holdem/
│

├─ js/
│  ├─ ui.js                   API 통신, 재접속, 화면 렌더링

│  ├─ deck.js                 덱과 셔플
│  └─ poker.js                최강 5장과 족보 비교
│
├─ server.js                  HTTP 서버, API, 정적 파일 허용 목록
│
├─ server/
│  └─ rooms.js                방, 세션, 개인별 상태, 서버 턴 타이머
│
├─ package.json               실행 / 테스트 명령
├─ start-server.cmd           Windows 서버 실행
│
├─ tests/
│  ├─ run-tests.js            포커 엔진 자동 테스트
│  └─ multiplayer.test.js     멀티플레이 및 실제 HTTP 통합 테스트
│
├─ README.md
└─ TEST-RESULTS.md
```

브라우저에는 다음 파일만 정적으로 제공됩니다.

```text
index.html
style.css
js/ui.js
```

덱 상태, 비공개 Hole Card, 다른 플레이어의 참가 토큰 등 민감한 게임 상태는 서버에서 관리합니다.

## 현재 제한사항

- 게임 상태는 서버 메모리에 저장됩니다.
- 서버가 재시작되면 생성된 방과 진행 중인 게임 상태가 사라집니다.
- 요청이 없는 방은 12시간 후 정리됩니다.
- 브라우저 탭을 닫아 참가 토큰을 잃어버린 경우 기존 좌석 복구를 보장하지 않습니다.
- 계정 / 비밀번호 / 별도 복구 키 기능은 없습니다.
- 대기실에서 퇴장한 좌석을 다른 플레이어로 교체하는 기능은 없습니다.
- 강퇴 기능은 없습니다.
- 진행 중 새로운 플레이어의 참가 기능은 없습니다.
- 관전 기능은 없습니다.
- 네트워크 지연 또는 브라우저 백그라운드 제한으로 상태 반영이 0.8초보다 늦어질 수 있습니다.
- 턴 종료 판정은 서버 시간을 기준으로 합니다.
- 단일 서버에서 친구들과 플레이하는 규모를 대상으로 설계했습니다.
- 여러 서버에 게임 상태를 분산하는 구조는 구현하지 않았습니다.
- 영구 게임 기록 저장 기능은 없습니다.
- 로그인 / 회원가입 기능은 없습니다.
- 데이터베이스를 사용하지 않습니다.
- Docker 설정은 포함되어 있지 않습니다.
- Rebuy 기능은 없습니다.
- Blind 자동 상승 기능은 없습니다.
- 현금 결제 또는 실제 화폐 기능은 없습니다.
