# FRIENDS HOLD'EM — 멀티플레이 버전

서로 다른 장소의 2~4명이 **각자 자신의 브라우저**로 같은 서버에 접속하는 텍사스 홀덤입니다. 이전 버전의 화면 넘기기는 제거했습니다. 방 코드, 대기실, 개인별 홀 카드, 공통 게임 상태 동기화를 지원합니다.

## 실행

서버를 실행하는 컴퓨터에 Node.js 22 이상이 필요합니다. 참가자는 브라우저만 있으면 됩니다. 외부 npm 패키지는 없어 `npm install`은 필요하지 않습니다.

압축을 풀고 `holdem` 폴더에서:

```sh
node server.js
```

해당 컴퓨터에서 `http://localhost:3000`을 열면 됩니다. `npm start`도 같은 명령입니다. **index.html 더블클릭이나 정적 파일 서버만으로는 멀티플레이가 작동하지 않습니다.**

Windows에서 터미널 명령 대신 `start-server.cmd`를 더블클릭해도 됩니다. 서버 창을 닫으면 게임 서버도 종료됩니다.

## 서로 다른 장소에서 인터넷으로 플레이

이 프로젝트를 **지속 실행 가능한 Node.js 서버를 지원하는 호스팅**에서 실행하고, 모든 플레이어가 그 서버의 같은 HTTPS 주소로 접속하는 구조입니다. 정적 HTML 전용 호스팅만으로는 동작하지 않습니다. 배포 작업과 특정 서비스의 배포 설정은 포함하지 않았습니다.

- 실행 명령: `node server.js`
- 기본 포트: `3000`. 호스팅 환경이 제공하는 `PORT` 환경 변수를 자동으로 사용합니다.
- 바인딩 주소: 기본 `0.0.0.0`, 필요하면 `HOST` 환경 변수로 지정합니다.
- HTTPS: 호스팅 플랫폼 또는 리버스 프록시에서 TLS를 처리하고 앱으로 전달합니다. API와 웹 화면은 같은 출처에서 제공합니다. 프록시는 원래 Host 헤더를 보존해야 합니다.
- 운영 단위: **Node 프로세스/인스턴스 1개**. 상태가 메모리에 있으므로 여러 인스턴스로 자동 분산하면 안 됩니다.
- 서버가 실행된 PC의 `localhost` 주소는 다른 장소의 친구가 접속할 수 있는 인터넷 주소가 아닙니다.

같은 Wi-Fi에서 시험하려면 서버 PC의 LAN IP와 포트로 접속할 수 있습니다. 운영체제/네트워크에서 해당 포트 접근을 허용해야 합니다. 이 프로젝트는 공유기나 방화벽 설정을 변경하지 않습니다.

## 플레이 순서

1. 한 명이 서버 주소에 접속해 2 / 3 / 4명을 선택하고 **방 만들기**를 누릅니다.
2. 친구에게 같은 서버 주소와 화면의 **8자리 방 코드**를 전달합니다.
3. 친구들은 각자의 브라우저에서 코드를 입력해 **참가**합니다.
4. 정해진 인원이 모이면 방장이 **게임 시작**을 누릅니다.
5. 각자 자신의 패를 볼 수 있고, 자신의 턴에만 행동 버튼이 활성화됩니다. 상대방의 미공개 카드는 서버 응답 자체에 포함되지 않습니다.
6. 핸드 종료 후 방장이 Next Hand 또는 New Game을 누릅니다. New Game은 현재 인원과 좌석을 유지하면서 칩을 초기화합니다.

한 PC에서 여러 명을 시험하려면 주소를 새 탭에 각각 직접 입력해 접속하거나 서로 다른 브라우저를 사용하세요. ‘탭 복제’는 브라우저에 따라 세션 저장소까지 복사하므로 같은 좌석으로 접속할 수 있습니다.

## 네트워크와 재접속

- 클라이언트는 약 0.8초 간격으로 개인화된 최신 상태를 조회합니다. 행동은 즉시 POST하고 결과를 받습니다. WebSocket이 아닌 HTTP 폴링 방식입니다.
- 좌석은 무작위 256비트 참가 토큰으로 인증합니다. 토큰은 URL이나 쿠키가 아닌 Authorization 헤더로 전송합니다.
- 참가 토큰은 탭의 sessionStorage에 저장합니다. 같은 탭에서 새로고침하거나 20초 이내에 연결이 복구되면 기존 좌석을 유지합니다. 진행 중 20초 이상 요청이 끊기면 해당 좌석은 리타이어 처리되며 재접속해도 복귀할 수 없습니다.
- 진행 상태는 서버에 있으므로 참가자의 새로고침이 게임을 초기화하지 않습니다.
- 자신의 턴이 아니거나, 화면이 오래되었거나, 요청을 중복 전송하면 서버가 거부합니다. 클라이언트의 칩/카드/승자 계산을 신뢰하지 않습니다.
- 턴은 **60초**입니다. 시간 초과 시 Check가 가능하면 Check, 아니면 Fold합니다. 연결이 끊긴 참가자 때문에 현재 핸드가 무기한 멈추지 않습니다.
- 접속 상태는 마지막 요청으로 판단하며, 10초 이상 요청이 없으면 연결 끊김으로 표시합니다.

## 포커 규칙

- 인당 10,000 Chip, SB 100 / BB 200. 첫 Dealer는 Player 1, 이후 생존 좌석으로 이동합니다.
- Heads-up에서는 Dealer가 SB이며 Pre-Flop 첫 행동, BB가 Flop 이후 첫 행동입니다.
- Fold, Check, Call, Raise, All-In과 자동 Call All-In을 구현했습니다.
- Raise 입력은 현재 스트리트의 **누적 베팅 총액**입니다. 직전 정상 레이즈 증분 이상으로 올려야 합니다. 부족한 스택은 All-In으로만 짧게 인상할 수 있습니다.
- 짧은 All-In에 대한 콜 기회와 재레이즈 권한을 구분합니다. 누적 인상이 정상 레이즈 폭에 도달하면 재레이즈를 허용합니다.
- 모든 활성 플레이어의 금액과 행동 완료 여부를 확인해 스트리트를 진행합니다. BB의 행동 기회를 유지합니다.
- 52장 셔플과 스트리트별 번 카드를 처리합니다. 실제 서버 셔플은 Node crypto 난수를 사용합니다.
- 7장 중 최강 5장을 완전 탐색합니다. 모든 10개 족보, 키커, A2345 Straight, 동점 분할을 처리합니다.
- 각자의 기여액별로 Main Pot / Side Pot을 나누고, Fold한 금액을 포함하되 수령 자격에서는 제외합니다. 미콜 금액은 반환합니다.
- 홀수 칩은 Dealer 왼쪽부터 승자에게 지급합니다.
- Showdown에서는 Fold하지 않은 플레이어의 패와 최강 5장을 공개합니다. Fold 승리에서는 상대 패를 공개하지 않습니다.
- 0 Chip은 다음 핸드부터 제외하며 마지막 생존자를 최종 우승자로 표시합니다.

## 파일 역할

```text
holdem/
  index.html                 대기실과 개인 플레이 화면
  style.css                  반응형 다크 테이블
  js/
    ui.js                    API 통신, 재접속, 화면 렌더링
    game.js                  서버에서 실행되는 게임 엔진
    deck.js                  덱과 셔플
    poker.js                 최강 5장과 족보 비교
  server.js                  HTTP 서버, API, 정적 파일 허용 목록
  server/rooms.js             방, 세션, 개인별 상태, 서버 턴 타이머
  package.json               실행/테스트 명령
  start-server.cmd            Windows 서버 실행
  tests/run-tests.js          포커 엔진 자동 테스트
  tests/multiplayer.test.js   멀티플레이와 실제 HTTP 통합 테스트
  README.md
  TEST-RESULTS.md
```

브라우저에는 `index.html`, `style.css`, `js/ui.js`만 정적 제공됩니다. 덱 상태, 비공개 홀 카드, 타인의 참가 토큰은 서버에만 보관합니다.

## 테스트

```sh
node tests/run-tests.js
node --test tests/multiplayer.test.js tests/result-display.test.js tests/disconnect.test.js
```

또는 `npm test`로 둘 다 실행합니다. 설치할 테스트 패키지는 없습니다.

## 현재 제한사항

- 서버 메모리 방식: 서버 재시작 시 모든 방과 진행 상태가 사라집니다. 요청이 없는 방은 12시간 후 정리합니다.
- 탭을 닫아 참가 토큰을 잃으면 기존 좌석 복구를 보장하지 않습니다. 계정/비밀번호/별도 복구 키는 없습니다.
- 진행 중 방장이 리타이어하면 남은 참가자에게 방장 권한을 자동 양도합니다. 대기실에서 떠난 좌석 교체, 강퇴, 중도 신규 참가, 신규 관전은 없습니다. 필요하면 새 탭에서 새 방을 만드세요.
- 네트워크 지연과 브라우저 백그라운드 탭 제한에 따라 반영이 0.8초보다 늦어질 수 있습니다. 서버 시간 기준으로 턴이 종료됩니다.
- 단일 서버에서 친구끼리 플레이하는 규모를 대상으로 합니다. 분산 서버, 대규모 부하 검증, 영구 기록 저장은 포함하지 않았습니다.
- 실제 외부 인터넷 배포와 브라우저 클릭 검증은 수행하지 않았습니다. 서버/API 및 게임 엔진 자동 테스트는 수행했습니다.
- 로그인, 데이터베이스, Docker, 리바이, 블라인드 상승, 현금 결제는 없습니다.

## 닉네임
방 만들기/참가 전에 닉네임을 최대 20자로 입력할 수 있습니다. 공백만 입력하거나 생략하면 좌석에 따라 Player 1, Player 2로 표시됩니다. 닉네임은 대기실, 프로필, 턴 표시, 로그, 행동/승리 알림에 반영되며 같은 세션의 재접속과 새 게임에서도 유지됩니다.

## 진행 중 퇴장과 리타이어
- 서버가 20초 동안 요청을 받지 못하면 퇴장으로 판단합니다. 창 닫기와 장시간 네트워크 단절은 동일하게 처리합니다. 기기 절전이나 브라우저의 백그라운드 정지도 20초 이상 통신을 막으면 리타이어될 수 있습니다.
- 현재 판에서는 다음 자기 행동 차례에 자동 Fold합니다. 이미 Fold했으면 추가 행동은 없고, 이미 All-In하여 행동이 끝났다면 현재 팟 자격은 유지하고 정산한 뒤 제외됩니다.
- 다음 핸드부터 카드, Dealer, Blind, 행동 순서에서 제외됩니다. 새 게임을 눌러도 퇴장 좌석은 되살아나지 않습니다.
- 이미 낸 베팅은 팟에 남습니다. 기권한 사람의 남은 칩은 0으로 소멸하며 다른 사람에게 지급되지 않습니다. 이후 반환 또는 All-In 정산이 있어도 기권자의 보유 칩은 0으로 유지됩니다.
- 남은 참가자가 한 명이면 현재 핸드 정산 후 최종 우승, 모두 퇴장하면 우승자 없이 종료합니다. 방장이 퇴장하면 남은 참가자에게 권한을 넘깁니다.

## 기권 버튼
게임 화면 오른쪽 맨 아래에 게임 기권 버튼을 배치했습니다. 확인창에서 기권 확정을 눌러야 적용되며, 기본 포커스는 계속 플레이입니다. 직접 기권과 20초 이상 연결 종료는 동일한 기권 상태로 처리합니다. 이번 판의 다음 자기 차례에 Fold하고 다음 핸드부터 제외되며 같은 방에서 복귀할 수 없습니다. 이미 All-In이면 현재 판 정산은 유지합니다.

기권자는 화면에 기권 · 패배로 표시합니다. 핸드가 이미 끝난 뒤 상대의 기권으로 최종 우승이 확정되더라도 최종 우승 안내를 한 번 표시합니다.
